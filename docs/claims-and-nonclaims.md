# Claims and non-claims

EACH (Evidence-Audited Cleanroom Harness) is a research project. This page is
the single authoritative statement of what EACH claims, and — more
importantly — what it explicitly does **not** claim. If any other document,
README, or UI language conflicts with this page, this page wins.

## What EACH claims

- EACH can record, for a given repair attempt, **exactly what the Builder
  model was allowed to see**: an approved spec, a declared set of source
  files, and prior validation feedback — nothing else.
- EACH can produce a **receipt** describing the model identity, the
  generation trajectory, validation results, and whatever post-generation
  similarity/license checks were actually run (and which were
  `UNAVAILABLE`).
- EACH can enforce an **information firewall**: once a candidate patch is
  produced and validated, the Auditor is a terminal boundary — no auditor
  finding is fed back into another Builder attempt.
- EACH can demonstrate, with adversarial tests, that its **sandboxed
  executor** denies outbound network access, does not inherit host secrets,
  and rejects patches that escape their declared scope.
- EACH can attest (sign and hash-bind) the artifacts of a run so a third
  party can verify they have not been tampered with after the fact.

These are **authoring-provenance engineering properties**: statements about
what information flowed where, and what was tested, that can be checked
mechanically.

## What EACH does not claim

- EACH does **not** certify legal clean-room status. "Clean-room" in this
  project describes an information-isolation engineering pattern, not a
  legal conclusion. Only a qualified attorney, informed by the specific
  jurisdiction and target project, can offer that.
- EACH does **not** certify originality or non-infringement of generated
  code. Its audit stage (exact/substring, n-gram, AST similarity, license
  scan, corpus-membership adapter) can **flag known-pattern matches**, but
  absence of a flag is not proof of independent creation. Training-corpus
  membership tools are incomplete and evolving industry-wide.
- EACH does **not** guarantee the generated patch is correct, secure, or
  idiomatic beyond passing the declared deterministic tests.
- EACH does **not** guarantee bitwise-reproducible model output. It
  distinguishes **input reproducibility** (the exact spec/materials/seed are
  recorded) from **output reproducibility** (re-running may yield a
  different patch).
- EACH does **not** imply that any destination project (including Xodus/
  xgameruntime) is willing or obligated to accept AI-assisted contributions.
  That decision belongs entirely to the destination project.
- EACH is **not** a UI, daemon, database, or hosted service. It is a local
  CLI harness that writes evidence to a private directory
  (`~/.each/`) and a public, sanitized repository.
- EACH's harness code may itself be developed with the help of AI coding
  assistants (Copilot/Architrave). That is a statement about how the harness
  was built, not about the target patches EACH produces, which are always
  generated by the declared Builder model (FixtureModel or a local model),
  never by the outer development assistant.

## Assurance is leveled, not binary

EACH assigns a run an assurance level (EACH-P0 through EACH-P4, see
`docs/threat-model.md`) describing how strongly isolation and provenance
evidence were actually verified for that specific run — not a fixed property
of the tool. A run on unverified native macOS execution is a lower assurance
level than the same run inside a proven no-network container, even if both
"succeeded."
